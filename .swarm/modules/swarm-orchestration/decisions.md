## 2026-08-15 — The module analyst fills whatever room it is given, so telling it to write less does not make it write less. Do not invent an unexplained magic number - whatever limits you choose, say in a comment why that number and not another. Keep MODULE_ANALYSIS_SCHEMA exported for the unsplit case so existing callers and index.ts keep working. Add a test that a split module's schema is strictly tighter than an unsplit one, and that the unsplit case is unchanged. npm test must pass.
