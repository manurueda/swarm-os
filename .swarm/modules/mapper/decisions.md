## 2026-08-15 — detectDrift in packages/core/src/mapper/pipeline.ts reports drifted: true whenever the repository digest hash differs from the recorded one, but changedModules only lists modules whose OWN files moved. Those two can disagree: the digest covers every tracked file, including files no module owns. Since .swarm/ became tracked, the map itself rewrites tracked files on every run, so immediately after a successful full map 'swarm status' prints the warning '0 module(s) changed since mapping' with an empty list - a warning that fires on a perfectly healthy repository. A signal that fires when nothing is wrong teaches people to ignore the signal, which is the one thing this project's own architecture notes say must not happen. Make drifted mean what its consumers use it for: there is module work to do. If no module's files changed there is nothing to re-analyse, whatever the whole-repo digest says. Keep reporting genuinely unanalysed modules as drift, since those need work regardless. Add tests covering both: a repo whose digest moved but no module did is not drifted, and a module with no recorded hash still is. npm test must pass.

- Follow-up: Could not run `npm test` in this session — the sandbox restricts filesystem access to the worktree directory, and this repo's node_modules is a symlink to /Users/manu/swarm-os/node_modules (outside the worktree), so every command that resolves it was blocked. Someone with access outside this sandbox should run `npm test` to confirm packages/core/src/mapper/pipeline.test.ts compiles and passes.

## 2026-08-17 — planAreas in packages/core/src/swarm/areas.ts is dead code. Nothing calls it: the only references are its own definition and the re-export in index.ts. Its decision - which of a module's detected areas still need surveying, and whether to split at all - was inlined into two separate places when the trigger became structural. survey-module-areas.ts now writes 'force ? areas : areas.filter(a => !recorded.has(a.slug))' and pendingSplits in pipeline.ts writes 'areas.some(a => !recorded.has(a.slug))'. Two copies of one rule, and the five tests in area-plan.test.ts now cover a function no production path reaches. This is precisely the failure this codebase just spent a session fixing: a decision that nothing calls, invisible because it looks alive. Restore planAreas as the single place that decision is made, with the structural trigger it has now, and call it from BOTH survey-module-areas.ts and pendingSplits so the rule exists once. Its tests must then be testing the real path. While there: pendingSplits takes a SwarmConfig it no longer uses - it is named _config - so drop the parameter and update callers; and SPLIT_AT in areas.ts is dead, kept alive only by index.ts re-exporting it, so remove both. Change no behaviour. npm test must pass.
