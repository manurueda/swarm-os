# Workspace & Git Worktrees — decisions

Append-only log. One entry per consequential choice, newest at the bottom.

## 2026-08-15 — Swarm OS links dependency directories into every agent worktree so agents can build, and then commits them. linkDependencies creates a symlink named node_modules; the conventional ignore rule in a JavaScript project is 'node_modules/' with a trailing slash, which matches a directory and not a symlink. So commitAll's 'git add -A' stages it, every mission branch ends up carrying an absolute path to one developer's machine, and changedFiles reports it as an ownership violation on every mission. The linked names are already available on WorktreeHandle.linked. Make the linked paths invisible to both commitAll and changedFiles, without depending on the target repository's own .gitignore and without modifying any file the developer owns. Add tests that create a real temporary git repository and prove a linked path is neither committed nor reported as changed. npm test must pass.

- Follow-up: mission/run.ts (a different module, outside my globs) still calls changedFiles(worktreePath, base) and commitAll(worktreePath, message) without the new third argument, and discards handle.linked (it goes out of scope after the worktree-creation try block). It needs a small change — capture `handle.linked` in an outer-scoped variable and pass it as the third argument to both calls — to actually close this bug end-to-end in production; without that change this module's fix only benefits direct callers of the git wrapper, not the real mission-run path.
- Follow-up: npm test / npm run build could not be executed in this session due to sandbox/permission restrictions blocking all code-execution commands; needs to be run in an environment where that's possible before merging.
